<objective>
Author the two semantic token JSON files that alias primitive values to design-intent names. These files express WHY a color is used, not WHAT it is. Semantic tokens are the public API that designers and engineers consume — never the primitives.

Purpose: Semantic tokens are the critical abstraction layer. When the brand green changes, only the primitive changes and all semantics update automatically. If semantics contained raw hex values, a brand change would require touching dozens of files. All 24+ semantic color aliases and 14 type style composites must reference primitives exclusively.

Output: tokens/semantic/color.json and tokens/semantic/typography.json. After this plan, npm run build:tokens must exit 0 with fully resolved token output.

SEMANTIC COLOR MAPPING (light surface values from spec §04):
Surface:
  color.surface.base     → {color.white}          #FFFFFF
  color.surface.sunken   → {color.grey.100}        #F5F5F5
  color.surface.raised   → {color.white}           #FFFFFF (light) — note: same as base but semantically distinct
  color.surface.inverse  → {color.grey.950}        #0F0F0F

Text:
  color.text.primary     → {color.grey.950}        #0F0F0F
  color.text.secondary   → {color.grey.500}        #808080
  color.text.disabled    → {color.grey.300}        #C9C9C9
  color.text.accent      → {color.green.700}       #7D9220  ← IMPORTANT: green.700 not green.500 (accessibility)
  color.text.onInverse   → {color.white}           #FFFFFF  (text on dark/inverse surfaces)

Action:
  color.action.primary    → {color.green.500}      #C6FF2D  ← background only
  color.action.primary.fg → {color.grey.950}       #0F0F0F  ← foreground on primary (always black)
  color.action.secondary    → {color.grey.950}     #0F0F0F
  color.action.secondary.fg → {color.white}        #FFFFFF

Border:
  color.border.subtle    → {color.grey.200}        #EBEBEB
  color.border.strong    → {color.grey.950}        #0F0F0F
  color.border.focus     → {color.green.500}       #C6FF2D  (focus ring — green outlines, not fills)

Status:
  color.status.live      → {color.green.500}       #C6FF2D

DTCG nested object format for semantic color (NO flat dot-keys in JSON):
```json
{
  "color": {
    "surface": {
      "base": { "$type": "color", "$value": "{color.white}", "$description": "Primary light surface" }
    },
    "action": {
      "primary": { "$type": "color", "$value": "{color.green.500}", "$description": "Primary CTA background. Background only — always pair with color.action.primary.fg." },
      "primary": {
        "fg": { "$type": "color", "$value": "{color.grey.950}", "$description": "Foreground on primary action (Electric Green background). Always Volt Black." }
      }
    }
  }
}
```

CAUTION on nested keys: "primary" and "primary.fg" from the spec table map to nested JSON:
{ "primary": { "fg": { ... } } } but "primary" itself also has a value.
SD handles this by allowing both a token value at "primary" AND children at "primary.fg" using the same object — { "primary": { "$type": "color", "$value": "...", "fg": { "$type": "color", "$value": "..." } } }.

SEMANTIC TYPOGRAPHY COMPOSITES (14 styles):
Each style is a composite referencing multiple primitives:
```json
{
  "type": {
    "display": {
      "xl": {
        "$type": "typography",
        "$value": {
          "fontFamily": "{font.family.display}",
          "fontSize": "{font.size.display.xl}",
          "fontWeight": "{font.weight.display.xl}",
          "lineHeight": "{font.lineHeight.display.xl}",
          "letterSpacing": "{font.tracking.display.xl}"
        },
        "$description": "display.xl — 40/42/700 Manjari. Headlines, hero statements."
      }
    }
  }
}
```
Repeat for all 14 styles. Use $type: typography for composite styles.
