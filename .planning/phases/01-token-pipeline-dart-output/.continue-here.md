# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: SD v4 DTCG token access — `token.value` is UNDEFINED in SD v4 with `usesDtcg: true`. Always use `token.$value`. Transforms store results in `token.$value`, not `token.value`. Violating this silently produces empty output.
- [ ] CONSTRAINT: dart-theme formatter is STATIC — it does NOT iterate over dictionary tokens to build ThemeData. It emits a hardcoded Dart file that references token constant names from voltventure_tokens.dart. The formatter ignores token values and produces the same output every build. Only the import path and constant identifiers need to match.
- [ ] CONSTRAINT: `dart` not in Git Bash PATH — all `dart` commands must run in PowerShell or a Flutter-aware terminal. Do NOT attempt `dart analyze` from bash.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| token.value in SD v4 DTCG | Using `token.value` instead of `token.$value` produces undefined/empty output with no error | blocking | Always access `token.$value`; add explicit comment in formatter code |
| Dynamic ThemeData formatter | Iterating dictionary tokens to build ColorScheme/TextTheme fields — field names and values are fixed spec, not token-driven | advisory | dart-theme.format.mjs returns a single hardcoded string; only token constant names (colorActionPrimary etc.) are injected |
| Colors.red placeholders | Using `Colors.red` or any placeholder for unresolved ColorScheme fields | blocking | Use `ColorScheme.fromSeed()` — fills all required fields automatically; copyWith overrides explicit ones only |
